# simkit 0.0.0.9000

## New features
* `sim_catalog()` scans a root directory for `simkit` result folders and returns a `SimCatalog` -- a tibble subclass, so `dplyr::filter()` and friends work directly on it -- with one row per experiment found, reporting each one's status (`"complete"`, `"partial"`, or `"errored"`), progress, size, and provenance. `sim_load()` reconstructs a `SimResults` from a single-row catalog entry (e.g. `cat[1, ]` or a `dplyr::filter()`-narrowed catalog), ready for `sim_collect()`.
* `sim_bootstrap()` wraps an estimator function as a drop-in [sim_method()] `fn`, running `B` bootstrap resamples of the observed data and appending the requested summaries of the resulting statistic to the point estimate: `output = "se"` adds `$se`, `output = "ci"` adds `$ci_lo` and `$ci_hi` (never a combined `$ci` field). `parallel = TRUE` dispatches the `B` resamples via a nested `future` plan; `simkit` warns via `cli::cli_warn()` if the outer and inner worker counts together would oversubscribe the machine's cores.
* `sim_scenario_grid()` expands a named list of parameter values (scalars held fixed, vectors varied factorially) into one `SimScenario` per combination via `expand.grid()`, naming each with a user-supplied `name_fn(params)`. The result carries class `SimScenarioGrid` and can be added directly to a `SimDesign` with `+`, just like a single `sim_scenario()`. Duplicate names produced by `name_fn` across the grid are a hard error, consistent with `sim_design()`'s uniqueness rule.
* `sim_evaluate()` maps user-supplied metric functions of the form `function(sims, truth)` over every (scenario, method) pair's successful replicates, returning a long-format tidy tibble. Replicates that failed during `sim_run()` are excluded automatically. A metric that errors, or returns something other than a single numeric value, degrades to `NA` for that cell with a single `cli::cli_warn()`, rather than aborting the rest of the evaluation. `sim_summarize()` pivots that tibble to one row per (scenario, method) pair and one column per metric.
* `sim_run()` dispatches replicates via `future.apply::future_lapply()` when the design has `sim_parallel(backend = "future", workers > 1)` configured. Per-replicate seeds are drawn from a single L'Ecuyer-CMRG stream chain keyed by each (scenario, method, replicate) triple's fixed position, so parallel runs reproduce sequential results exactly under the same design seed, regardless of dispatch order or worker count. A `dgp` or method `fn` with a large captured environment triggers a `cli::cli_warn()` before dispatch, since that environment will be serialized to every worker.
* `sim_check()` performs a pre-flight validation of a `SimDesign`, running a small number of trial replicates of every (scenario, method) pair sequentially in an ephemeral scratch directory, and reporting per-pair pass/fail status, timing, and an ETA for the full run (adjusted for configured parallel workers). `sim_run(check = TRUE)` runs this automatically and aborts before the real run if any pair fails.
* `sim_run()` executes a `SimDesign` sequentially, checkpointing each replicate to disk immediately upon completion and supporting `on_error = c("warn", "skip", "stop")` fault tolerance.
* `sim_collect()` reads on-disk replicate results into a tidy tibble, from either a storage path or the `SimResults` handle returned by `sim_run()`.
* `sim_run()` writes `manifest.json` (design metadata, seed, timestamps, `design_hash`) at the end of a run, and an `in_progress.json` marker while a run is underway.
* `resume = TRUE` (the default) skips replicates already checkpointed to disk; re-running with a conflicting design at the same storage path aborts with a clear error.
* Core S3 classes `SimDesign`, `SimScenario`, `SimMethod`, `SimParallel`, and `SimStorage`, with constructors, validators, and print methods.
* `+.SimDesign` assembles a design from scenarios, methods, and configuration, returning a new (unmutated) design each time.

* Initial CRAN submission.
